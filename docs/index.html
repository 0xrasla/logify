Powerful Features

Designed for modern Bun apps

Elysia Native

Fitted precisely to Elysia's lifecycle events. Zero setup with high-resolution execution timelines and zero overhead.

Colorized Streams

Color-coded methods and HTTP status symbols (2xx/3xx/4xx/5xx) so your eyes track health in real time.

Structured File Logging

Autocreates log folders and writes organized chronological entries to disk for production reviews.

IP Resolution

Resolves and appends inbound client IPs, including fallbacks for proxy servers behind standard cloud loads.

Path Filtering

Bypass request logging for system endpoints (like /health, /metrics, or assets) to keep logs clean.

100% Type-Safe

Engineered in TypeScript. Ships with type auto-completion and rigid validation for all customization setups.

Quick Start

Three Lines Integration

Simply load and register the logger() middleware into your Elysia chain. It begins tracking your incoming web traffic instantly, printing clear, beautifully aligned console lines with zero custom parameters required.

Want specific formats or filters? Just supply your properties to the logger(...) options.

index.ts 
import { Elysia } from "elysia";
import { logger } from "@rasla/logify";

const app = new Elysia()
  .use(logger())
  .get("/", () => "🦊 Hello World!")
  .listen(3000);

console.log("🦊 Elysia server running at localhost:3000");
service.ts 
import { 
  initializeLogger, 
  debug, 
  info, 
  warn, 
  error 
} from "@rasla/logify";

// Configure once in your entry file
initializeLogger({
  level: "debug",
  file: true,
  filePath: "./logs/app.log"
});

// Execute log commands anywhere in your application
debug("Init db connection pool...");
info("System health checked: OK");
warn("Database query latency: 154ms");
error("Failed to retrieve user ID: 219");
Global Logger Instance

Application-Wide Messaging

Logify packs a global instance. Instead of injecting custom middleware variables through domain components, simply instantiate Logify's settings once in your setup file via initializeLogger(...).

You can then import clean functions directly: debug(), info(), warn(), and error(). Keep your layers separated and imports simple.

Configuration

Tailor Every Property

Configure outputs, toggle disk writes, bypass custom route endpoints, and customize terminal strings using rich, modular formatting tokens.

Explore a reference options structure you can feed directly into your initialization configurations:

options.ts 
{
  // Console logs (default: true)
  console: true,

  // File logging (default: false)
  file: true,
  filePath: './logs/app.log',

  // Log level limit (default: 'info')
  level: 'debug', // 'debug' | 'info' | 'warn' | 'error'

  // Skip routes (avoid health or assets spam)
  skip: ['/health', '/metrics'],

  // Display client IP (default: false)
  includeIp: true,

  // String format tokens (see right playground!)
  format: '[{timestamp}] {level} [{method}] {path} - {statusCode} {duration}ms'
}
